# 上限つき繰り返し・段階 1 の独立手計算

ADR 0066 の段階 1（種類 1・4）の受入。数値は模型の仮定であり実測値ではない。
引継ぎの採取 JSON は正解に使わない。以下は受入担当が分数で計算し直したもの。
[R] 計算の根拠は各経路の所要と宣言された条件付き確率。所要、分布、出口、gap、
資源容量や既存の非先取り dispatch の規則を変えれば、この手値を適用できない。
旧 DSL の手展開は `witnesses/`、新構文の固定入力は `models/` に分ける。
手展開は spike の adapter や展開済み入力から作らず、次の経路を直接記述する。

## L1: 非決定

審査 1 分、不合格なら修正 2 分。合格する第 k 回の終了は 3(k−1)+1。
したがって P, FP, FFP, FFF は done@1, done@4, done@7, escalated@9。
review starts は 1,2,3,3、fix starts は 0,1,2,3。待ちがないので work=elapsed。
非決定に確率を割り振らず、完了性や reachable は全経路について検査する。
N=32 では done@1..94（3 分刻み）、escalated@96。最大 Task 数は 64。

### 2 案件・同時到着・同じ容量 1 の Rev と Clerk

案件の番号を入れ替えた順序を両方数え、一つの同時刻順序に固定しない。
先に Rev を使う案件を A、後を B とする。両方 FFF では資源占有は次のとおり。

- Rev: A[0,1), B[1,2), A[3,4), B[5,6), A[7,8), B[9,10)。
- Clerk: A[1,3), B[3,5), A[5,7), B[7,9), A[9,11), B[11,13)。
- escalated は A@11、B@13。案件番号を交換すれば各案件の最遅が 13。
- 片方が最初に合格すれば、もう片方は待ちなしの FFF で 9 に到達できる。
  各案件の escalated の elapsed は [9,13]、work は [9,9]。
- 合格の最早は最初の審査で 1。最遅は B が FFP、A が FFF の場合の B@10。
  途中の合格はそれ以後の占有を取り除くので、これより遅い審査を作らない。
  各案件の done の elapsed は [1,10]、work は [1,7]。
- 両案件を合わせた review starts は [2,6]、fix starts は [0,6]。
  非決定性に確率は付けない。独立 reference と engine に別々にこの包絡を照合する。

## L2: 固定不良

初期 bad の質量は 1/10、good は 9/10。審査も修正も bad を変えない。
good は最初に合格し、bad は 3 回とも不合格となる。

- done@1 = 9/10、escalated@9 = 1/10。
- E[work] = E[elapsed] = 9/10 + 9/10 = 9/5。
- E[review starts] = 9/10 + 3/10 = 6/5。
- E[fix starts] = 0 + 3/10 = 3/10。
- N=32 でも escalated = 1/10（時刻 96）。毎回引き直す 1/10^32 ではない。
- clock=6 では good の done 9/10 は既知、bad 1/10 は未完了。
  escalated 確率は [0,1/10]、実到達数は 0、inconclusive / exit 2。
  第 2 回修正までの時刻 6 に達しても業務上の第 3 回を済ませたことにはならない。
  done の出力区間は [9/10,1]。下限は既に到達した 9/10、上限はそこに切断された
  未判定の 1/10 を加えた保守的な上界である。escalated の下限 0 は未到達、
  上限 1/10 はその未判定質量。上限への加算は、その質量を完了として数える意味ではない。
  切断のない L2 の done の点確率と、L2-clock の既知質量・保守区間を混同しない。

## L3: 修正が潜在を変える

bad を修正した後も bad のまま残る確率は 1/4。合格に必要な修正は前の回の修正。
最後の修正が good に変えても次の審査はなく、その経路は escalated のまま。

- done@1 = 9/10。
- done@4 = (1/10)(3/4) = 3/40。
- done@7 = (1/10)(1/4)(3/4) = 3/160。
- escalated@9 = (1/10)(1/4)^2 = 1/160。
- 累積 done は 9/10, 39/40, 159/160。
- 合計は (144+12+3+1)/160 = 1。
- E[elapsed] = (144×1+12×4+3×7+1×9)/160 = 222/160 = 111/80。
- E[review starts] = 1+1/10+1/40 = 9/8。
- E[fix starts] = 1/10+1/40+1/160 = 21/160。
- N=32 の escalated は (1/10)(1/4)^31、done の最遅は 94、escalated は 96。

## L4: 回数を観測した kernel

各回の不合格の条件付き確率は 1/2,1/5,1/10。

- done@1 = 1/2。
- done@4 = (1/2)(4/5) = 2/5。
- done@7 = (1/2)(1/5)(9/10) = 9/100。
- escalated@9 = (1/2)(1/5)(1/10) = 1/100。
- 累積 done は 1/2,9/10,99/100。
- E[elapsed] = (50+40×4+9×7+1×9)/100 = 282/100 = 141/50。
- E[review starts] = 1+1/2+1/10 = 8/5。
- E[fix starts] = 1/2+1/10+1/100 = 61/100。
- N=32 は 3〜32 回の不合格率が各 1/10。escalated は
  (1/2)(1/5)(1/10)^30 = 1/10^31。最遅の時刻は L1 と同じ。

## P1: 再確認

第 k 回は [31(k−1),31(k−1)+1)。次の回がある場合だけ 30 分待つ。
入荷が見えたら 5 分の出荷を行う。潜在 ready は最初に一度だけ引く。

| ready | 質量 | 終端 | lead time | work | intentional | check starts |
|---|---:|---|---:|---:|---:|---:|
| r1 | 1/2 | shipped | 6 | 6 | 0 | 1 |
| r2 | 1/8 | shipped | 37 | 7 | 30 | 2 |
| r3 | 1/8 | shipped | 68 | 8 | 60 | 3 |
| never | 1/4 | gave_up | 63 | 3 | 60 | 3 |

- shipped = 1/2+1/8+1/8 = 3/4、gave_up = 1/4。
- 累積 shipped@6,@37,@68 は 1/2,5/8,3/4。
- E[work] = (4×6+7+8+2×3)/8 = 45/8。
- E[elapsed] = (4×6+37+68+2×63)/8 = 255/8。
- E[check starts] = (4×1+2+3+2×3)/8 = 15/8。
- 各固定経路では in_service+intentional=lead time。他の待ち区分は 0。
  非固定経路の区分 min/max は同じ経路の値とは限らないため、和の検査は
  引継ぎ試験の対象と、固定経路の全区分を両方残す。
- N=32 でも r1〜r3 の出荷は同じ。never の終了は 32+31×30=962、work=32。
- clock=40 では r1,r2 の shipped 質量 5/8 だけ既知、残り 3/8 は未完了。
  shipped は [5/8,1]、inconclusive。gave_up の到達ではない。

## 故障の対

固定した L2 の bad を各回独立に引き直す模型では (1/10)^3=1/1000。
L3 の修正を無効にすると escalated=1/10。
L4 の全回を第 1 回の確率で扱うと (1/2)^3=1/8。
P1 の最終回にも gap を入れると gave_up=63+30=93、work は 3 のまま。
これらの新しい模型の出力が、元の手値 assertion に拒否されることも検査する。
clock 切断を done/escalated に寄せた合成観測、Task の開始時刻の上書き、
reference だけ 2 回に減らした模型も元の assertion で拒否する。

## 旧出力の契約

期待を書く前に既存の CLI 試験 `simulation.rs` と `response_loss_close.rs`、
core の `report.rs` と `explain.rs` の event 型を読んだ。simulate は反例のない safety を satisfied とせず
inconclusive、案件の終端は case_outcomes、trace は actor と capability が別欄。
新試験はこの形を使い、未実装のフィールドを仮定して旧出力を不合格にしない。
指標の平均欄は仮定せず、上の確率と固定経路から分数を導出する。

設計書 v0.2 の冒頭は実装不存在と書くが、現行には parser/lower/engine がある。
設計の来歴として読み、実行と出力契約は現行コードに従う。
