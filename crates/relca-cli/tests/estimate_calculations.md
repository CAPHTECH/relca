# ログ推定の手計算

合成ログだけを使う。以下の手値は実装出力から採取しない。R01 以外の観測対では、記した一箇所だけを変える。模型やログを変更した対では、hash 不一致を試す対を除いて spec の hash をその新しい bytes から計算する。

## E01: 4 案件の結果と所要時間

窓は閉区間 [0,1] 分。操作 `A.run` は各案件で一度、start=0、finish=1。結果は順に pass、fail、pass、fail。両端点は全案件で true、Actor と実行者は明示対応。モデルの一行 `K` は pass/fail 各 1/2、モデルの固定所要は 1 分。指定は kernel 1 行と時間 1 件、`min_samples=1`、`max_support=4`、`decimals=2`。

二枝の kernel に M=1 は使えない。各枝を数えると 2、窓内にある唯一の正の整数分 1 を加えて M=3。信頼水準 γ=1079/2048 と置くと、α=(1−γ)/6=323/4096。

pass と fail は各 hits=2, n=4, unknown=0。候補は各 2/4=1/2、DSL は各 `0.50`。p=1/8 で X≥2 の確率は `1−(7/8)^4−4(1/8)(7/8)^3=(4096−2401−1372)/4096=323/4096`。対称性で上端は 7/8。宣言 1/2 は候補と一致し、区間内。参考点は枝順に `[1/8,7/8]`, `[1/2,1/2]`, `[7/8,1/8]`。

時間は 1 分が hits=4, n=4、候補 4/4=1、DSL は `1.00`。片側下端の式は p⁴=323/4096、上端は 1。D=1048576 とし、`4096×555661⁴ < 323×D⁴ < 4096×555662⁴`。よって表示する下端は 555661/1048576。平均 `(1+1+1+1)/4=1`、中央の 2 個の平均は 1、最小・最大・四分位も 1 分。平均の区間は null。参考点は全て 1 分で、選んだ固定値ではない。両スロットの丸め誤差上限は 1/100。ヘッダは1行目、観測に使った行は 2–9。未知なし、exit 0。

## 観測の対

区間の検算では、下端に対し `T(n,x,p)=Σ[i=x..n] C(n,i)p^i(1−p)^(n−i)` を使う。厳密解が格子の外のときは、下の表の分数を分母 D に直した整数 t について、`T(n,x,t/D) < α < T(n,x,(t+1)/D)` を有理数のまま比較すればよい。上端は `1−L(n,n−hits−unknown)`。例えば n=3, x=2 は `3p²−2p³`、n=4, x=1 は `1−(1−p)^4`。

| n | x | 下端 L | 比較する式 |
|---:|---:|---|---|
| 2 | 1 | 2637/65536 | 1−(1−p)² |
| 3 | 1 | 885/32768 | 1−(1−p)³ |
| 3 | 2 | 180701/1048576 | 3p²−2p³ |
| 3 | 3 | 56207/131072 | p³ |
| 4 | 1 | 21313/1048576 | 1−(1−p)⁴ |
| 4 | 2 | 1/8（厳密） | 1−(1−p)⁴−4p(1−p)³ |
| 4 | 4 | 555661/1048576 | p⁴ |

| ID | E01 からの一変更 | 手値と判定 |
|---|---|---|
| E02 | min_samples を 5 にする | n=4 は変わらない。両候補 null、区間は E01 と同じ。`insufficient_samples`、exit 2 |
| E03 | 案件1の Task 両イベントの Actor ID を未対応の同一 ID に変える | 一つの対応失敗。両スロット n=3。pass/fail の hits は 1,2、候補は 1/3,2/3、DSL は 0.33,0.67。区間は `[885/32768,867875/1048576]` と `[180701/1048576,31883/32768]`。時間の 1 分 3/3 の下端は 56207/131072。未対応 Task は n へ入れず、未知数に足して分母を戻さない。exit 2 |
| E04 | K の条件を潜在の bool に替え、両行の枝は E01 と同じ | 要求した行に標本を配らない。周辺は pass 2、fail 2。`latent_condition`、`not_derivable`、exit 4 |

| E08 | K の二番目の枝の結果名だけを pass にする | result だけでは二枝が区別不能。候補 null、`branches_not_distinguishable`、exit 4 |

## 反復の対

R01 は `repeat laps at_most 3` の本体直下に `A.run` が一箇所。対象の `requires`・別資源や勤務表なし、単一案件の直列模型。モデルは `given [laps.round]` で 1、2、3 の三行（各二枝）を持つ。無条件の対照では同じ枝を `*` に置く。log の案件は4件で、Task の出現数は順に 1,2,3,3。各案件で start=0,2,4 のうち該当するもの、finish=start+1。結果は、0 始まりの案件添字と出現添字の和が偶数なら pass。第1回の pass/fail は 2/2、第2回は 2/1、第3回は 1/1。要求するのは kernel のみ。いずれも三回×二枝で M=6、γ=55/1024 なので α=323/4096 と一致する。

| ID | 一変更 | 手値と判定 |
|---|---|---|
| R01 | 基準、別対照で given を無条件にする | n=4,3,2、pass の候補は 1/2,2/3,1/2。第3回は各枝区間 `[2637/65536,62899/65536]`。条件付きは exit 0。`*` は親候補 null、`round_pooling_not_supported`、同じ三回分の表だけを出す（exit 4） |
| R02 | 第4案件の2番目の start を初回と同時刻にする | 行順で tie を解かない。第4案件の全回を未知へ、各回 unknown=1、`round_order_ambiguous`。既知の n−unknown は 3,2,1。exit 2 |
| R03 | 第4案件に4番目の観測を加える | 第4案件の全回が未知。各回 unknown=1、残りの既知数は R02 と同じ。`rounds_exceed_model_limit`、exit 2 |
| R04 | 反復本体に二つ目の A.run を置く | 番号なしの出現分布 `[{observations:1,cases:1},{observations:2,cases:1},{observations:3,cases:2}]`。候補 null、`ambiguous_call_site`、exit 4 |
| R05 | E01 の案件1にもう一つの Task を加える | 同一案件に2観測を別標本として入れない。候補 null、`multiple_observations_per_case`、exit 2 |
| R06 | 反復の最初の回だけ wait して again する枝を追加し、呼出しを else 側に置く | RoundGate 型。唯一の呼出しでも最初の観測が第2回でありうる。番号なしの件数だけ、`round_not_identifiable`、exit 4 |
| R07 | R01 の Capability に `requires laps.round >= 2 else denied` を追加 | RequiresRound 型。文は本体直下で最初だが、最初の回は未開始。第2回と第3回の観測を第1回・第2回にしない。番号なしの件数だけ、`round_not_identifiable`、exit 4 |

## I01: 指定と切断

E01 の独立した対で必須欄を一つ落とす、未知欄を一つ足す、ログ hash を 64 桁の別値にする。いずれも exit 3、候補なし。別対でログの最終 event 行だけ LF を除いて 65537 bytes にする。有効な行の prefix を読めても exit 2。hash・n・区間・候補・観測出所の全てを null とし、`truncated` を返す。header 超過の invalid とは分ける。
## 独立レビュー後の追加手値

- V31: E01 の `decimals` だけを 0 にする。配分単位は1。`1/2, 1/2` の床は各0、余りは各1/2。同率で先頭にだけ残り1単位が付き、結果は各1、0となる。後者も2件観測しているので、この配分は出さない。両枝 `dsl: null`、厳密な `1/2, 1/2` と区間は残し、`dsl_precision_insufficient`、exit 2。時間の一点分布は `dsl: "1"` のまま。
- V32: 30案件のうち29件は pass・1分、1件は fail・2分。各候補は 29/30 と 1/30。`decimals=1` のとき、10倍して 9+2/3 と 0+1/3、床に足す残り1単位は先頭へ配分され 1.0 と 0.0。kernel と時間分布の両行とも `dsl: null`、厳密値は残し exit 2。
- V33: E01 の後ろ2案件は start だけを残す。n=4、unknown=2、打切り2。既知は pass と fail が各1。最低4件には足りないので両スロット候補なし、区間・件数は保持する。kernel 各枝の区間は `[L(4,1),1−L(4,1)] = [21313/1048576,1027263/1048576]`。最低2件に切り替えると kernel の候補は各1/2、coverage は partial のまま。時間分布は打切りで候補なし。確認用ページでは、両枝の宣言値と候補が一致しても出所として確定せず、既知2/4・unknown=2・打切り2・partial と表示する。
- V34: R01 のモデルに同時に2案件が到着する設定を追加する。IR の `bounds.cases` は2。並行処理・未開始の拒否はないので、案件が資源を待っても同じ案件の第2回が第1回を追い越せない。第2回の n=3、件数2・1、候補 2/3・1/3 は R01 と同じ。
