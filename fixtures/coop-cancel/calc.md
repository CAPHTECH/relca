# coop-cancel

## 手計算

単位は分。ADR 0001 の取消応答は要求から 1〜d tick 後であり、d = 1 なら 1 分後しか無い。
設計 v0.1 §6.1・§6.4・§18 の取消要求と取消完了の区別に従う。
capacity 2 と work-conserving により両枝は時刻 0 に開始する。結果は pass のみ。

| 経路(開始イベント順) | a の占有区間 | b の占有区間 | 採用/取消要求 | ack/drain 完了 | 作業量 |
|---|---|---|---|---:|---:|
| a, b | [0, 3) | [0, 4) | a、時刻 3 | 4 | 3 + 4 = 7 |
| b, a | [0, 3) | [0, 4) | a、時刻 3 | 4 | 3 + 4 = 7 |

時刻 3 の a の pass を採用して b に取消要求。b は時刻 4 に ack し、その時刻まで容量を占有する。
通常終了予定は時刻 5 なので、終了と ack の同時競合は無い。b は取消完了し、結果の pass は返さない。
経過は 4 分、作業量は 7 分、result_at は 3 分。取消要求だけで b の 3 分以降の作業を消してはならない。

tie の同時候補は無い。drain 後の a == pass は真なので done に進み、定義済みの no_match は到達不能。
reachable end.done と全体は satisfied。生存 Task は最大 2、clock 4 分ちょうどで終わり切断は無い。
ADR 0002 により Cut は undeclared、警告 W-CUT-0 を期待する。
未決: なし。手計算のみで、実装との照合はしていない。
