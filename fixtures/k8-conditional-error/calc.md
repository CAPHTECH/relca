# V01-10: 条件付き誤り

設計 v0.1 §18、設計 v0.2 §22.1 の継承行。実行前に固定した手計算。
確率の単位は受付1件当たり(無次元)、時間・作業量は分。

初期誤りは 0.02 = 1/50、正しい入力は 49/50。
誤り条件下の見逃し(pass)は 0.20 = 1/5、検出(fail)は 4/5。
正しい入力は必ず pass。潜在 wrong は kernel だけが読み、方策は観測 v で分岐する。

- 誤りかつ pass: (1/50)(1/5) = 1/250 = 0.004。
- 誤りかつ fail: (1/50)(4/5) = 2/125。
- 正しい入力かつ pass: (49/50)(1) = 49/50。
- accepted: 49/50 + 1/250 = 123/125、rejected: 2/125。和は1。

Check.inspect は時刻0開始、時刻1終了。どの経路も elapsed=work=1分。
verify probability reached #1 は上限0.004ちょうどで satisfied、全体 satisfied/exit0。
切断なし。潜在を方策が読むことも非決定の一様化も無い。

模型の単一故障対broken-miss-rateは見逃し率だけ0.25(補確率0.75)へ増す。逃避率は(1/50)(1/4)=1/200となり、上限0.004を超えて同じ検査がviolated/exit1。
broken-tight-upperは上限だけ0.003へ狭める判定の比較の対として残す。確率1/250は変わらずviolated/exit1で、模型故障の代わりとはしない。
確率的違反専用の診断コードは現行契約に無いので、診断を捏造せず性質idとverdictで検出する。
